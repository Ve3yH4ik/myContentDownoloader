# Робоче місце 0.2 — 2026-11-11

## Джерело й рішення

Користувач надав два скриншоти головного вікна Content Downloader X1: меню «Файл», панель інструментів, звичайні/повторювані границі, редактор шаблону, права панель функцій, генератор URL, Sitemap/список адрес та окреме вікно звіту. У запиті уточнено, що налаштування, редактор шаблону, вебсканер та інші інструменти мають відкриватися в нових вікнах.

Використано структуру взаємодії. Вихідний код, піктограми та графічні ресурси оригіналу не копіювались. Скриншоти не задають достовірну граматику макросів чи внутрішню логіку CDX1.

## Реалізовано

- Нативне меню «Файл / Налаштування / Сервіс / Web / Інтерфейс / Довідка», робочі open/save/new, масштаб і повний екран.
- Світле робоче місце: toolbar, HTTP, дерево звичайних/повторюваних і вкладених границь, шаблон, результати, права панель, генератор, черга URL.
- Реальні окремі BrowserWindow для HTTP/проєкту, шаблону, границь, вебсканера, звіту й версій проєктів. Повторне відкриття активує існуюче вікно.
- Стан проєкту в Electron main; вузький preload API; застосовані зміни синхронізуються між вікнами. Валідація схеми перед застосуванням/збереженням. Під час виконання зміни заблоковані, звіт можна переглядати.
- Шаблон: текст, вставлення макросів у позицію курсора, preview на останніх даних, застосування й збереження.
- Границі: дерево з enabled-checkbox у головному вікні та окремий JSON-редактор повного дерева children/pipeline.
- Вебсканер: HTTP HTML href / XML Sitemap loc, relative URL та base href, нормалізація, deduplication, same-origin filter, передавання до черги. Ліміт 10000 адрес; без JavaScript/рекурсивного crawling.
- Генератор: `{num}`, from/to/step, валідація й обмеження 10000 адрес, додавання до черги без дублікатів.
- Черга: послідовний запуск, продовження після помилки, stop, спільний JSON/CSV із `_url`; шаблон виконується на кожному документі окремо. COUNT/INDEX_ID залишаються локальними для документа. Документ і trace показують останній успішний документ.
- Звіт сеансу: URL, успіх/помилка, рядки, тривалість, HTTP/помилка; останні 1000 записів, live sync, CSV export.
- SQLite versions зберігає нові налаштування; старі конфігурації v1 відкриваються з defaults.

## Файли

Основні зміни: src/desktop/main.ts, preload.ts, worker.ts; src/renderer/main.tsx, style.css; src/core/schema.ts, engine.ts; tests/core.test.ts, tests/ui/desktop.spec.ts; README.md, package.json/lock та документація.

Нові модулі: src/core/links.ts (HTML/Sitemap links), src/core/generator.ts (URL ranges), src/shared/api.ts (typed multiwindow API), цей звіт.

## Перевірки

- 19 Vitest-тестів: існуюче ядро, links/HTML base/Sitemap/index, dedup/filter, generator ranges/errors, нові defaults/roundtrip.
- TypeScript strict і production build.
- 2 Playwright/Electron-тести: основний наскрізний сценарій; окремі вікна/меню, shared settings, template preview/sync, HTML+Sitemap scan → queue, generator, queue з HTTP 404 → продовження, звіт, save/open усіх нових налаштувань, boundary edit, зупинка.
- Вигляд головного вікна й звіту перевіряється за screenshots тестів; локальні test-results не комітяться.

## Обмеження й наступні кроки

Це робоче місце для вже реалізованого ядра, не повна копія CDX1. Спеціалізований form/Monaco-редактор границь, перенесення/збереження геометрії панелей, pause/resume, browser automation, AST правил CDX1 та інші пункти початкового плану залишаються. Звіт живе в пам'яті поточного сеансу; recovery прогресу черги не реалізовано. Скриншоти не підтверджують синтаксичну сумісність CDX1.

## Перевірити вручну

1. `npm.cmd start` у папці D:\AI\myContentDownoloader; для локального прикладу окремо `npm.cmd run fixture`.
2. Кнопки «Налаштування», «Редактор шаблону», «Вебсканер» і «Звіт» відкривають самостійні вікна.
3. Застосувати налаштування/шаблон; запустити документ; перевірити таблицю й preview шаблону.
4. Сканувати дозволену HTML-сторінку/Sitemap, додати URL до черги, запустити чергу та відкрити звіт.
5. Зберегти проєкт; через «Проєкти» відкрити версію й перевірити відновлення налаштувань.
