# Вікно налаштування границь — 0.5.0

Дата: 2026-11-12. Джерело візуальної структури — наданий користувачем скриншот: HTML угорі, сторінка нижче, URL праворуч, активна границя та пошук елемента за F4. Код, піктограми й графічні ресурси оригінальної програми не копіювались.

## Що працює

- Окреме збільшене вікно в дизайні 0.4; відкриття конкретної границі з головного дерева, повторний виклик фокусує вже відкрите вікно.
- Вибір активної границі, звичайні/повторювані/вкладені вузли, додавання й видалення, enabled, name та стабільний ID. ID/повне дерево можна змінити через JSON із перевіркою унікальності.
- Поля between start/end, Regex expression/flags, CSS expression; reverse, skip, MIN/MAX, repeat, separator. Це працюючі параметри наявного ядра.
- Ordered pipeline: trim, HTML→text, lowercase, singleLine, required, fallback, prepend/append, trimEndCharacters, literal/Regex Replace. Власні параметри операцій, додавання/видалення та зміна порядку.
- Останній отриманий HTML доступний без нового завантаження. Кнопка «Завантажити сторінку» відкриває вибраний URL у виділеному headless Chromium, із RequestProfile, cookies/proxy/secret references. Він не перериває браузер Browser Automation.
- HTML/DOM над сторінкою, literal-пошук у коді, змінювана висота панелі коду. У верхньому полі можна виділити текст і призначити його початком або кінцем границі.
- Наведення на елемент + F4 або клік у режимі вибору: знаходить саме цей елемент, виділяє його код і обводить його в preview. Показує CSS та XPath; можна призначити CSS або відкривальний/закривальний теги.
- Вибір через elementFromPoint не натискає кнопок/посилань сайту. Окремий вимикач режиму вибору дозволяє звичайні кліки для переходів; коліщатко прокручує реальну сторінку.
- Ctrl+клік у HTML знаходить найглибший елемент у цій позиції та прокручує сторінку до нього. Позиція відкривального тега батьківського елемента вибирає батьківський вузол.
- Кнопка пошуку CSS на сторінці пов’язує вручну введений селектор зі сторінкою й кодом.
- URL праворуч — поточний URL проєкту та його черга без дублікатів. Натискання завантажує цей документ у редактор.
- Preview виконується у Worker Thread з поточним незбереженим деревом та вибраною границею в контексті її батьків. Інші кореневі вузли/сестринські границі не підміняють контекст. Показує значення, кількість, проміжні операції та журнал. Виводяться перші 100 значень, щоб не перевантажувати UI.
- «Застосувати» оновлює визначення границь головного проєкту; «Застосувати й зберегти» додатково записує нову версію в SQLite. Preview сам не змінює проєкт і не запускає чергу. Для нового загального результату після зміни границь потрібно запустити проєкт.
- JSON лишається додатковим режимом, а не єдиним редактором. Незастосований JSON захищений від випадкового перемикання границі; зовнішні зміни не переписують локальний незбережений draft.

## Технічна основа

`source-inspector.ts` використовує parse5 location info через Cheerio. Це дозволяє розрізняти однакові повторювані HTML-блоки й текст, схожий на теги, всередині script/comment. Індекси узгоджені з UTF-16 позиціями textarea; CSS ID екрануються. `boundary-tree.ts` містить незалежні immutable edit/focus helpers.

Схему браузерних дій винесено у легкий `browser-actions.ts`: worker парсингу більше не завантажує Playwright. Запуск worker та виконання парсингу мають окремі дедлайни; ліміт Regex починається після запуску worker, а не під час імпорту модулів.

Вікно має окремий BrowserEngine і не використовує Electron renderer для виконання отриманого HTML. Сторінка показується інтерактивним знімком Chromium із накладеною рамкою вибору; це не native WebContentsView і не відеопотік. Код після завантаження — серіалізований DOM (`page.content()`), який може відрізнятися від початкових HTTP-байтів.

F4/зворотний пошук стосуються основного документа. Вибір усередині cross-origin iframe/shadow DOM не заявляється реалізованим. XPath доступний для інспекції елемента; окремого XPath parser adapter цей етап не додає. CSS-парсер повертає inner HTML, як у чинному ядрі; для атрибутів можна застосувати Regex до HTML.

## Перевірки

Production build успішний; `npm test` — 52/52, `npm run test:ui` — 5/5 (Electron із локальним fixture). У зібраному worker відсутній імпорт Playwright.

У packaged runtime (`release/win-unpacked/Universal Data Downloader.exe`) повторно пройшли всі 5 UI-тестів. Portable EXE окремо відкрито з PATH лише до System32: HTTP і bundled Chromium працюють без Node/npm у PATH. Перший smoke з лімітом 60 с не дочекався розпакування; з довшим стартовим очікуванням перевірка успішна. Portable містить Chromium і перед запуском розпаковує файли, тому старт на навантаженому ПК може бути повільним.

Артефакт: 331700735 байтів; SHA-256 `03FA0D1DC6C94CA3F244D40C5CFB76152D422C02B6FE91ACCA6B969875C4E7E5`. Копію в папці результатів перевірено за тією самою контрольною сумою.

- Core: точне зіставлення повторюваних елементів, UTF-16/український текст, батьківський тег, script/comment, escaped ID, void elements, nested tree operations і preview через батьківську повторювану границю.
- Chromium fixture: вибір без click side effect, source range, точний батьківський елемент, XPath та перехід до елемента в документі.
- Electron: native F4 за координатами preview, native Ctrl+клік у textarea, призначення CSS/start/end, два результати вкладеної границі, порядок Replace/Prepend, збереження та повторне відкриття конкретного вузла, захист незастосованого JSON.
- Повні regression suites HTTP/browser/proxy/settings/design/queue збережено. UI-очікування обмежені 20 секундами замість фіксованих 5; це дає браузеру час відкритися на навантаженому Windows ПК, помилки операцій усе одно перевіряються.
- Локальний fixture — власний тестовий каталог, без залежності від стороннього сайту.
