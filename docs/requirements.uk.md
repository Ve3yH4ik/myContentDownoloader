# Проєкт: Universal Data Downloader — функціональний аналог Content Downloader X1

## 1. Роль і мета

Ти — senior software architect і full-stack розробник.

Необхідно розробити Windows-програму, яка відтворює функціональні можливості Content Downloader X1 від SBFactory, але має сучаснішу архітектуру, покращений інтерфейс, розширену систему границь парсингу та повністю керований порядок виконання операцій.

Програма призначена для роботи з будь-якими даними: HTML, текстом, JSON, XML, CSV, API, файлами, базами даних і браузерними сторінками.

**Головне правило:** не створювати демонстраційний макет із кнопками без функціональності. Кожна реалізована дія повинна мати працюючий обробник, збереження налаштувань, виконання та перевірку результату.

Не копіювати вихідний код, графічні ресурси або захищені компоненти SBFactory. Створити власну реалізацію.

## 2. Технології

- Electron — Windows desktop.
- React + TypeScript — інтерфейс.
- Node.js + TypeScript — ядро.
- Playwright + Chromium — браузер.
- SQLite — локальне сховище.
- Monaco Editor — редагування коду та макросів.
- React Flow — візуальний редактор сценаріїв.
- Worker Threads / дочірні процеси — ізольоване виконання.
- Vitest — модульні тести.
- Playwright Test — інтеграційні та UI-тести.

Архітектура повинна дозволяти запускати ядро без Electron.

Передбачити переміщення, зміну розмірів і приховування панелей.

### 3.2. Редактор границь

Кожна границя повинна підтримувати:

- Власну назву й ID.
- Увімкнення та вимкнення.
- Джерело даних.
- Початкову й кінцеву границю.
- Regex, CSS, XPath, JSONPath.
- Пропуск входжень.
- Пошук у прямому або зворотному напрямку.
- Повторюваний режим.
- Мінімальну й максимальну кількість результатів.
- Роздільники.
- Вкладені границі.
- Пошук-заміна.
- Власні макроси.
- Умови.
- Попередній перегляд.
- Обробку помилок.

**Критична вимога:** дозволити вкладати звичайні границі в повторювані, повторювані у звичайні та повторювані в повторювані без жорсткого обмеження глибини.

### 3.3. Редактор повторюваних границь

Відтворити функції, показані на скриншотах:

- Окремі налаштування кожної повторюваної границі.
- Макрос `[VALUE]`.
- Поля «Що замінити» та «На що замінити».
- MIN, MAX, SEP, SOURCE.
- Роздільник значень циклу.
- Роздільник циклів.
- Призначення звичайних границь усередині активної повторюваної.
- Виведення результатів у шаблон.

Додати необмежену кількість повторюваних вузлів, підтримку масивів та об'єктів.

### 3.4. Редактор шаблону виведення

Створити два режими:

**Режим сумісності:**
- Табличний редактор CSV.
- Текстовий редактор шаблону.
- Вставлення макросів.
- Посилання на границі.
- Генерація результату.
- Попередній перегляд HTML, TXT, CSV.

**Новий режим:**
- Візуальний конструктор результату.
- Drag-and-drop полів.
- Формування вкладених JSON/XML.
- Динамічні колонки.
- Умовне виведення.
- Власні шаблони.

### 3.5. Бібліотека макросів

Розробити реєстр макросів із категоріями:

1. Отримання даних.
2. Границі парсингу.
3. Текст і регулярні вирази.
4. HTML, CSS, XPath.
5. JSON і XML.
6. CSV і таблиці.
7. Математика.
8. Умови та логіка.
9. Змінні та лічильники.
10. Файли й зображення.

13. Черги й потоки.
14. Бази даних.
15. Користувацький код.
16. AI-операції.

Для кожного макросу реалізувати:

- Назву.
- Опис.
- Синтаксис.
- Параметри.
- Значення за замовчуванням.
- Приклади використання.
- Перевірку параметрів.
- Виконання.

Макроси, підтверджені скриншотами, включають `[VALUE]`, `[IF]`, `[IF2]`, `[COUNT]`, `[INDEX_ID]`, `[CHECKCHANGES]`, `[ADDFINALDOCUMENT]`, `[RELOADDOCUMENT]`, `[MORE_THREADS]`, `[WAIT]`, `[SETCOOKIES]` та інші.

Не припускати, що їхній синтаксис повністю відомий. Спочатку реалізувати реєстр специфікацій і тести сумісності.

# Доповнення до ТЗ — модуль Advanced Text Processing

Розробити повноцінний рушій пошуку-заміни та додаткових налаштувань границь парсингу на основі наданих скриншотів Content Downloader X1.

## Обов'язкові компоненти

### A. Boundary Post-processing

Реалізувати налаштування:

- fallbackText
- prependText
- appendText
- trimEndCharacters
- htmlToText
- required
- transliterate
- lowercase
- singleLine
- shuffleLines
- trimWhitespace
- replaceRules

Усі операції повинні бути доступні в керованому pipeline, де користувач сам визначає порядок виконання.

### B. Replace Rules Engine

Створити рушій правил із підтримкою:

- Звичайного пошуку-заміни.
- Регулярних виразів.
- Операторів пропуску символів.
- Захоплення та повторного використання фрагментів.
- Умовних операторів.
- Змінних.
- Фільтрації рядків.
- Перетворення регістру.
- HTML-aware замін.
- Обробки JSON.
- Керування виконанням правил.
- Виконання по рядках.
- Вкладених операцій.

### C. Сумісність

Створити парсер синтаксису CDX1.

Парсер повинен перетворювати текстові правила на внутрішнє AST (Abstract Syntax Tree).

Не виконувати правила простим послідовним String.replace без аналізу операторів.

Для кожного оператора створити:

- Специфікацію синтаксису.
- Валідатор.
- Виконавець.
- Приклади.
- Автоматичні тести.

Невідомі оператори не ігнорувати мовчки. Відображати повідомлення про непідтримуваний синтаксис.

### D. Інтерфейс

Редактор повинен мати:

1. Поле введення правил.
2. Панель бібліотеки операторів.
3. Автодоповнення синтаксису.
4. Підсвічування операторів.
5. Перевірку синтаксису.
6. Попередній перегляд.
7. Результат до та після обробки.
8. Покрокове виконання.
9. Історію операцій.
10. Можливість змінювати порядок правил.

### E. Тести

Створити контрольні приклади для:

- `{skip}` із кількома входженнями.
- `{get}` та захоплення фрагментів.
- `{case_down}`.
- `{reset_if_nil}`.
- `{break_if_nil}`.
- `[FILTERSTRINGS]`.
- `[LINEMODE]`.
- `{SETVARIABLE}`.
- HTML-aware замін.
- Вкладених правил.

Перевіряти не лише кінцевий результат, а й проміжні значення та порядок виконання.

Не вважати сумісність із CDX1 підтвердженою, доки результат не порівняно з оригінальною програмою.
